# 核心采集与项目理解

## Problem Statement

用户需要信任 session 信息收集完整，并能得到有明确目标、标题与描述的项目。现有实现存在漏采与截断；合并直接生效，缺少 session 选择及基于原始证据的预览。

## Solution

修复采集故障，明确显示各来源覆盖与缺口；保留可追溯正文，按项目目标组织工作。合并先选择范围、读取证据生成结构化草稿，确认后应用同一份结果并支持撤销。

## User Stories

1. 用户能采集含中文和 emoji 的长消息，无超限重试死循环。
2. 用户关闭已观察的 Herdr pane 后仍能收齐末尾结论。
3. 用户的归档历史跨越单轮预算时仍能继续补采。
4. 用户能区分在线、目录发现、正文收齐和不可恢复的缺口。
5. 用户能发现配置了但从未成功上报的采集来源。
6. 长消息尾部的目标和完成条件不会因摘要预算从原始证据中丢失。
7. 项目根据共同目标与交付结果聚类，而非根据 session、目录或单个话题拆分。
8. 标题表达交付对象，描述表达问题、范围与结果，完成标准可验证。
9. 用户选择整项目或其中若干 session 合并。
10. 用户在正式变更前看到完整项目草稿、关联变化和证据缺口。
11. 预览失败不会改变项目；确认时应用所见内容。
12. 预览后源数据变化时系统拒绝过期提交并允许重新生成。
13. 合并关联由事务确定性应用，不依赖模型自行调用工具。
14. 用户能撤销合并，恢复关联及项目字段。

## Implementation Decisions

沿用现有采集器、SQLite 领域事件与撤销、LLM runner 和管理员鉴权。保留既有字段锁、否决、忽略及上游拒绝隔离。

用户于 2026-11-13 确认的产品决定（不再是待定建议）：

- 任务与规格用仓库内本地 Markdown，不建 GitHub Issues。
- 项目按“可独立验收的目标”聚类。
- 部分合并：移动所选 session 的项目关联，保留来源项目及未选关联。
- 整项目合并：才把来源项目标记为 merged。
- 预览必须明确展示上述变化。
- 移动的是项目关联：不删除原始 session、证据或历史事件，不影响该 session 与其他项目的关联；目标已有相同 session 时去重。

合并闭环的验收要求：

1. 选择来源、目标，以及整项目或 session 子集。
2. 证据集合 = 目标现有 session + 选中来源 session。
3. 从用户目标、问题、范围、交付结果和完成标准重新构建项目；旧标题和摘要只作参考，不拼接、不作事实锚点。
4. 长历史分批读取并汇总，记录输入覆盖与缺口；未选 session 的内容不混入部分合并。
5. 生成可验证的结构化草稿，展示标题、简介、价值、完成标准及关联变化。
6. 预览不改变正式项目、正式关联或阶段。
7. 确认后事务应用预览中的确切结果，不重新调用模型。
8. 关联迁移与去重由确定性代码执行。
9. 预览记录输入签名；项目、关联、证据变化后拒绝过期提交并允许重算。
10. 模型失败、输出无效、并发变化不留下半次合并。
11. 保留事件、审计和撤销。
12. 部分移动后检查来源项目剩余内容，不暗中合并整个来源。

必须保留：用户锁定字段、删除记录、否决和忽略不能被 AI 绕过；预览中确认覆盖锁定字段须展示具体变化；被上游拒绝的 session 不重试、不缩窗、不跳过、不换模型重发，显示缺口；不为历史采集启动/恢复 agent；不自动对真实项目做合并实验。

## Testing Decisions

在现有公开行为边界验证：采集器→HTTP→入库；合并预览/确认 API→项目查询及撤销；界面选择→预览→确认。每个故障先写能复现的行为测试，再做最小修复。复用现有 fake daemon、临时 transcript 和独立数据库。最后跑类型检查、完整测试和前端构建，并做 Standards/Spec 审查。

## Out of Scope

不为读取历史启动或恢复用户 agent。不自动合并生产项目。不重新提交被上游拒绝的会话。不将 mock 测试或来源心跳等同于真实机器的全量对账。
