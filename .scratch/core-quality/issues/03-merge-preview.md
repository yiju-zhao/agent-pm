# 03: session 粒度合并预览与确认

**What to build:** 用户选择合并范围，查看根据原始证据生成的项目草稿，确认后原子应用并可撤销。

**Blocked by:** 02

**Status:** implemented, not deployed

- [x] 支持整体和 session 子集；预览写明每个 session 的关联变化和来源项目的去向。
- [x] 预览不写正式项目；证据为目标已有 session 加选中来源 session 的已存正文；部分合并不含未选 session 和来源旧记录。
- [x] 确认应用所见内容（不再调用模型），关联确定性迁移与去重，失败回滚。
- [x] 过期预览拒绝；忽略、拒绝隔离及缺口可见；同一时间只生成一份预览。
- [x] 撤销恢复关联、来源阶段和目标文字。
- [x] API、界面、类型检查、构建及双轴审查通过（审查发现与处理见下）。

## 审查后仍保留的取舍

- 带 `merge_into` 的 `/stage` 接口仍可不经预览直接合并（AI 提议的合并题确认后也走它）；它现在确定性关联来源 session，但不会恢复用户从目标取消过的关联。
- 应用时写入的字段随即锁定；撤销恢复文字，但锁保留（与其他用户编辑的撤销行为一致），预览里有说明。
- 输入签名包含证据 session 的内容量：目标项目里有仍在产出内容的 session 时，预览容易过期，需要重新生成。这是按「证据变化后拒绝过期提交」实现的，是否放宽待用户决定。
- 预览调用被模型提供方拒绝时只标记该预览失败，不写入 session 的拒绝隔离记录（无法归到单个 session）；不会自动重试，「重新生成」是用户的手动操作。
- session 数超过 24 个时每个 session 只读最近一段，模型调用数等于 session 数。
- 读取的是整个 session 的正文，不按关联的时间范围裁剪；提示词要求只采用服务于该目标的内容。
- 预览不生成里程碑/todo；确认后由已有的项目整体整理（会调用模型）处理，来源项目的描述也在那时重整。
- 合并草稿的模型调用记为 `curate` 角色，会更新调度器状态里的最近整理时间。
- `headTail` 在采集器和中心各有一份实现（采集器是独立编译的二进制，未跨层引用）。
