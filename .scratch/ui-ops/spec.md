# 中央控制台式界面（ops console）

用户于 2026-11-15 要求：用专业、稠密、偏 Palantir 一类数据控制台的风格重做前端；从第一性原理考虑放什么、不放什么、如何对齐与引导；让用户统一管理不同 session 的信息，达到"智能中央控制"，并能用于复盘和总结；用不同的可视化表达不同重点。

## 用户在这里要完成的事（按频率）

1. **现在有什么需要我？** 待决定的问题、等我操作的 session、阻塞、采集异常。——行动队列，按紧急程度排序，每条只给一个去处。
2. **我的 agent 们现在在干什么？** 每台机器上的 session、状态、在为哪个项目工作、哪些没有归属。——运行态势（机器泳道 × session 状态）。
3. **每个目标进行到哪了？** 阶段、进度、最近是否有动静、阻塞。——项目组合表（一行一个项目，可扫读、可排序）。
4. **这段时间发生了什么？（复盘）** 精力花在哪、做出了哪些决定、完成了什么、哪里停滞。——时间 × 项目热力图、关键事件时间线、按项目的阶段总结。
5. **给我一份总结。** 选时间段，按项目生成可复制的 Markdown 报告。

## 不放什么

- 首页不再放项目大卡片：卡片一屏只能看三四个，组合判断需要的是对齐的列。
- 不做装饰性图表：每张图必须回答上面某个问题，并能点进去。
- 不在总览重复编辑功能：编辑留在项目页；总览只负责发现和跳转。

## 信息架构

左侧导航栏：指挥台（`#/`）、项目（`#/projects`）、复盘（`#/review`）、Session（`#/sessions`）、Inbox（`#/inbox`）、接入密钥（`#/keys`）。顶栏：理解层状态、同步、连接、设置。

## 视觉

深色控制台：近黑底、略亮的面板、1px 分隔线、小号大写标签、等宽数字、蓝色强调、绿/琥珀/红只表达状态。圆角 2–4px。网格对齐：面板标题、数字列、状态列统一基线。全部经 `tokens.css` 的 token，不写颜色字面量。

## 数据

新增只读接口 `GET /activity?days=N&tz=<分钟>`（可选 `project`）：按天、按项目统计会话正文量（经 session 关联归属，一个 session 关联多个项目时各算一次）、按机器统计，以及时间段内的关键事件（决定、完成的 todo / 里程碑、阶段变化、阻塞新增 / 解除、新项目、合并），不含已被撤销的事件。

## 验收

- 指挥台四个区域、复盘三类可视化、总结复制，均有行为测试。
- 原有页面（项目、项目详情、Session、Inbox、密钥、设置）功能不变，现有测试按新的导航与路由调整后通过。
- typecheck、build:web 通过；用演示库在浏览器里逐页截图检查对齐、对比度和空状态。
