agent-pm 是用户所有 coding agent 共用的项目看板。你的对话已经被采集器自动收进中心，由一个整理员（PM）读摘要后更新看板。你通过 MCP 服务 `agent-pm` 的 `pm_*` 工具和它打交道：读是事实，`pm_report` 是给 PM 的线索。工具的参数和返回格式写在各工具的描述里。

## 开工

1. 用 `pm_search`（任务里的关键词）或 `pm_list_projects` 找这项任务所属的项目。找不到就当它是新课题，照常干活，在第一次上报时说明是什么新课题。
2. 对找到的项目读 `pm_get_brief`：阶段、完成标准、当前里程碑、未完成 todo、阻塞、最近决策、正在做它的其他 session。简报不够再读 `pm_get_project`。

完成标志：你能说出这项任务对应哪个项目（或确认它是新课题）、它的完成标准，以及有没有别的 session 正在做同一件事。

简报里的决策和完成标准是用户已经认定的约束。你的方案和它冲突时，先问用户，再动手。

## 上报

`pm_report` 只在出现以下**里程碑事件**时调用，每件事一次，写在事情发生之后：

- **决定**：选定了方案、否掉了方向、改了范围。写决定本身和理由。
- **完成**：一个里程碑或完成标准里的一条满足了。写满足的依据：哪些测试通过、哪个 PR 合并、哪个产物交付。
- **阻塞**：在等用户、等外部、或卡在技术问题上。写卡在哪、需要什么才能继续。
- **新课题**：冒出一件看板上没有的事。写它是什么、为什么值得做。

写法：只写事实和依据，用一两段话；`project_hint` 填项目 id（没有就填标题）。过程细节、代码改动的逐条描述已经在你的对话里，PM 会从对话里读到，上报只写对话里不显眼的结论。

`pm_report` 不改看板：阶段、优先级、完成与否由 PM 和用户决定。上报写「发生了什么」，把「该怎么改看板」留给 PM。

## 回答用户

用户问项目进度、优先级、有哪些 agent 在做什么时，用 `pm_list_projects`、`pm_get_brief`、`pm_timeline`、`pm_list_sessions` 查，回答时说明依据是看板的哪一项。

## 优先级和阶段

看板上的优先级和阶段只取固定选项，定义如下，读简报和回答用户时按它理解：

- **P0** 最高：阻塞其他工作或有硬期限，现在就要做。**P1** 高：当前主线，本周要推进。**P2** 中：重要但不紧急，排进计划。**P3** 低：可选，有空再做。
- **idea** 只有想法；**explore** 在调研或试验，方向未定；**build** 方向已定、在正式产出；**verify** 主体做完、在检验；**done** 完成；**parked** 用户决定暂停；**abandoned** 用户决定不做；**merged** 并入另一个项目。

## 接入

工具不可用时（`pm_*` 不在工具列表里），这台机器还没接入：告诉用户，按仓库 README 的「各台机器上的 agent 接入 MCP」配置 `agent-pm` 和 `mcpToken`。只用 `mcpToken`；别的 token 一律不放进 agent 的配置。
