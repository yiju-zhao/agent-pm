后端设计：Session × Project 项目管理助手

一句话原则：对项目的所有改动都是一个带出处的"操作"。AI 和你调用同一套操作；网页上的按钮、AI 的工具、MCP 只是同一层操作的不同入口。

0 · 整体结构

① 采集不用 LLM
每分钟拉各机器 herdr 快照；发现 agent 从运行中变成空闲/完成时，通过 ssh 读对话的新增部分
→
② 摘要员Haiku · 每个 session 增量跑一次
输出课题、决策、进展、todo、阻塞、悬而未决的问题
→
③ 整理员Sonnet · 每 30 分钟或攒够一批
调用工具改项目，拿不准就提问
→
领域操作层唯一能改状态的地方
校验状态机、字段锁、证据
SQLite（表 + 事件日志）
对外三个入口：HTTP API（网页）· MCP（整理员 / 任何机器上的 Claude Code / Claude App）· CLI（脚本、hook）

1 · Session 怎么记录

身份

来源:机器:agent类型:原生session_id
例：herdr:gx10-090e:claude:0d67da1f-…
• herdr 的 pane_id 移动后会变，只作属性，不当主键
• 没有原生 ID 的（部分 codex）：先用 herdr:机器:terminal_id 临时登记，标"低精度"（只能读屏幕），拿到真实 ID 后合并
• 游标：记录对话 JSONL 读到哪，每次只读新增

Session 生命周期（临时的）

运行中⇄等待⇄空闲→已结束→已清除
• 前三个状态直接来自 herdr
• 已结束：从 agent 列表里消失
• 已清除：对话文件也没了
• 记录永远保留，它对项目的贡献不会丢

2 · Session 和 Project 的关系

contributions：session × project × 里程碑(可选) → 这段时间做了什么、置信度、AI 判断还是你指定。多对多。
置信度低于阈值的 session 进首页的"待归属"栏。

3 · Project 生命周期，以及 AI 能做什么

idea→探索→构建→验证→完成　　任意阶段 →　搁置放弃合并到 X
✅ AI 直接做 建新项目（idea 阶段）、挂 session、往前推进一步、增删改 todo / 里程碑 / 阻塞、记录决策
🟡 AI 只能提议 完成、放弃、合并、改你锁定过的字段：这些会自动变成一个问题来问你
🔒 你亲手改过的字段会被锁定
🧾 每个写操作都必须带 理由 和 证据（指向摘要或对话片段）
💤 "休眠"根据最近活跃时间算出来，只是显示状态；"搁置"是一个决定
规则写在领域操作层的代码里，不靠 prompt 约束。

4 · 问题 = 等你点头的操作

{
  "prompt": "Rea 逆向这个 session 属于哪里？",
  "kind": "choice",
  "options": [
    {"label":"新建项目",
     "op":"create_project",
     "args":{"title":"Rea 逆向","from_session":"herdr:mac-mini:claude:801a…"}},
    {"label":"归入 openlingo",
     "op":"link_session","args":{"project":"openlingo"}},
    {"label":"不追踪","op":"ignore_session"}
  ],
  "evidence":["digest:4812"]
}
• 你点按钮 → 后端以"你"的身份执行绑定的操作
• 填空题（kind:"text"）：你填的文字作为参数传进去，比如 update_project{done_criteria: …}
• 确认题（kind:"confirm"）：AI 提议"完成 / 合并"时使用
• 所以前端不需要知道每种按钮的业务逻辑，只要渲染选项、回传选了哪个

6 · 存储（一个 SQLite 文件）

采集与理解层

sessions 身份、机器、状态、对话位置、游标
chunks 对话片段
digests 摘要员输出的 JSON

项目状态

projects milestones todos decisions blockers
contributions session ↔ project
questions 问答箱

events：时间线、溯源、撤销都靠它

每个操作在同一个事务里先改表、再追加一条事件：{时间, 谁(ai:整理员 | 你 | 系统), 操作, 对象, 参数, 理由, 证据, 被谁撤销}。没有做完整的事件溯源，避免过度设计。

7 · MCP：要做

类别工具谁能调
读pm_list_projects pm_get_project pm_get_brief pm_timeline pm_search pm_list_sessions任何 agent
上报pm_report：作为一个上下文片段进入流水线，不直接改项目任何 agent
写create_project update_project transition_stage upsert_milestone upsert_todo record_decision set_blocker link_session ask_user只有整理员 + 你（网页）

为什么做 MCP

1. 整理员本身就是 Claude agent，MCP 是它调用工具最自然的方式
2. 任何机器上的 Claude Code 开工时调 pm_get_brief("dLLM")，就能拿到项目全貌和历史决策
3. "只要有 context 就能用"：任何 agent 都可以 pm_report 推上下文进来

为什么只有整理员能写 我的决定

十几个 agent 同时直接改项目，状态会被写乱。只留一个"大脑"直接写，其他 agent 只读和上报，状态保持一致。

8 · 技术栈 我的选择

一个 TypeScript 进程跑在 mac-mini 上：HTTP 服务 + SQLite + Claude Agent SDK（OAuth token 走订阅）+ MCP（streamable HTTP，其他机器通过 Tailscale 连接）。前端用 React。
